# v1: retrieval-augmented pipeline (retired)

The first version asked a simple question: how far can a multimodal LLM go if it is given an ECG textbook and the
cardiology guidelines to retrieve from? Its code is not in this repo, because v2 replaced it entirely. The design and
the evaluation that retired it are summarized here.

## Pipeline

1. **Quality gate and JSON extraction.** A first vision pass, with 8 real ECGs and their cardiologist reports as
   fixed few-shot examples in context.
2. **Report retrieval.** Search over an ECG textbook (215 chunks, ChromaDB, local MiniLM embeddings), using a query
   built from step 1.
3. **Second vision pass**, guided by a checklist of 33 patterns built from the first-pass findings.
4. **Plan retrieval.** Search over 11 guidelines (Brazilian Society of Cardiology, ACC/AHA, ACLS), 1,247 chunks.
5. **Synthesis.** A smaller model merges everything into report, plan and risk, formatted for a chat message.

The pipeline was served through a FastAPI endpoint, with a spreadsheet as storage and a first Telegram bot. The
average cost was about US$0.08 per ECG.

## Evaluation (cases with a cardiologist report, few-shot cases excluded)

| | Full pipeline (46 cases) | Zero-shot, image + patient data only (47 cases) |
|---|---|---|
| Triage normal vs. abnormal | accuracy 70%, sensitivity 81%, specificity 43%, PPV 76%, NPV 50% | — |
| Report text similarity to the cardiologist | 0.43 | 0.44 |
| Plan text similarity to the cardiologist | 0.31 | **0.43** |

Errors showed two patterns. Most false positives came from photos the model itself graded as partial or degraded.
Three of the six false negatives were on good photos with confidence 0.95, so the model was overconfident. The plan
was also more aggressive than the physicians': it activated the myocardial-infarction protocol where they would
order serial troponins.

## What changed because of it

- **Retrieval was removed.** A zero-shot model matched the report and beat the plan, so the textbook and guideline
  retrieval was adding cost and latency without adding value.
- **Text similarity was replaced** by a field-by-field comparison on a shared schema. A similarity of 0.43 says
  little about *which* finding was missed.
- **The bottleneck became explicit:** reading the tracing, plus writing in the physician's voice. v2 attacks the
  second; v3 measures the first.
